# Passkey 设备间迁移设计

日期：2026-11-08（香港）。范围为 #52 的显式、一次性迁移，不提供后台同步或第三方不可导出凭据的提取。本文是实现约束，不是已完成验收的声明。

## 授权与格式

只迁移 Locklark 生成并保存在加密金库中的软件凭据。浏览器页面、MAIN/isolated 桥、扩展存储和普通日志不得接触记录、用户句柄或私钥。迁移入口位于原生应用/CLI，使用完整因素解锁、明确的源条目/修订/凭据选择和单次提交许可；不增加浏览器远程导出操作。

接收端从已认证金库的现有 age X25519 设备身份生成邀请。邀请包含版本、随机邀请 ID、接收端公开 age recipient、审计签名公钥和短期限，并由接收端审计身份签名。邀请的自签名证明完整性，不证明对端身份；用户必须在两台设备上核对公开指纹。源端显式固定接收端指纹，接收端显式固定源端指纹。禁止自动接受包内自报的身份。

传输沿用已有 age 加密及 Ed25519 签名，不引入自制加密算法。包头只包含版本、包 ID、邀请 ID、公开发送者身份、目标指纹、期限、密文及签名。签名使用独立的迁移域，覆盖完整规范化包头及密文。加密正文包含所选凭据记录和必要的登录展示信息，不附带密码、备注、OTP、附件、其他凭据或整个金库身份。所有解码器拒绝未知字段、尾随数据、重复选择器、非规范编码和超限输入。

## 源端流程

1. 核对邀请签名、固定的接收端指纹、版本和期限；列出将披露的条目和公开凭据元数据。
2. 在一次已认证事务内重验每个源条目修订、活动状态、凭据 ID、完整记录及当前提交许可。
3. 只对确切选择的记录加密，产生完整签名包，并以独立已知审计动作记录 HMAC 绑定的选择器、对端和包摘要。审计不保存原始用户句柄、私钥或密文正文。
4. 成功提交审计后才能向原生调用者返回加密包。输出文件使用 owner-only 临时文件、同步和不覆盖发布；发布失败报告结果未知并保留审计依据，不自动重新披露。
5. 导出不删除源凭据，也不把“已生成包”表述为“接收端已持久化”。

## 接收端流程

1. 先核对显式固定的源端指纹、签名、邀请、目标 recipient、期限和容量，再使用已解锁身份解密。
2. 预览公开元数据和目标登录映射。用户确认创建新登录，或固定现有目标条目及其修订。拒绝把不兼容的 RP/用户身份自动合并到同一登录。
3. 在同一次事务内重新认证、检查邀请尚未使用/撤销/过期、重验所有目标修订和冲突，再赢得提交许可。
4. 按 `(条目 ID, 凭据 ID)` 应用精确映射，使用 #56 的版本化集合格式。相同凭据 ID 对应不同记录、目标存在歧义或任一选择器过期时整包拒绝；禁止覆盖、部分导入或最后写入者获胜。
5. 原子持久化全部目标凭据、邀请消费状态、签名快照及迁移审计。任何失败均回滚全部变化；提交后失去会话权限只能报告结果未知，不能返回私钥或假称未发生。
6. 单次邀请只接受一个包。已消费邀请/重复包拒绝重放。锁库、取消、到期和修订变化均通过现有 mutation gate 和审计验证阻止迟到提交。

## 凭据语义

- 保留 credential ID、RP ID、用户句柄和密钥；独立依赖方必须验证迁移前后的签名。
- 已有软件凭据使用 BE=1 和零签名计数器。迁移不得伪造平台认证器、UV 或硬件保证。BS 只在有可信持久化依据时改变，单纯输出文件不证明远端备份成功。
- 本地删除不是分布式吊销。离线接收端无法获知源端后续删除；用户需在依赖方撤销凭据。本文不承诺即时远程撤销、冲突同步或第三方硬件密钥导出。
- 迁移包及邀请元数据是敏感材料，使用私有文件和有界生命周期。错误仅输出固定类别，不包含因素、路径、请求正文或记录。

## 验收

自动化至少覆盖两套独立金库身份、相同依赖方的独立签名验证、错误接收者/源指纹、过期/撤销/重放、篡改、重复 ID、冲突、并发锁库/取消、事务回滚、包输出失败和备份恢复。测试进程/目录隔离不能称为“两台真实设备”。

#52 的最终关闭还要求两个真实设备的授权迁移和平台/硬件提供者共存证据。缺少这些条件时分别记录已实现接口、实际执行结果和未完成验收。
