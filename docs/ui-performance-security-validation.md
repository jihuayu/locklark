## 性能与一致性

弹窗先比较最多 500 行的公开渲染/筛选输入，只有变化时才做 URL 匹配、排序与重建。签名包括修订、标题、账号、收藏、标签、网址、字段标签、Passkey 公开元数据、筛选与支持状态，排除秘密字段值/原始详情。连接生命周期始终执行，不再被网站候选未变的提前 return 跳过。变化后的点击使用新修订；不变时保留节点、焦点和滚动。

同机 Chromium 合成组件：500 行、100 次 pending 状态切换，旧版约 988.7ms、增加/移除各 49,500 行；最终回归约 146.3ms、0 行重建且焦点/滚动保留。100 行约 257.3ms → 24.3ms。这是有运行负载差异的本地有限样本，不能推导真实站点 p95。

桌面 captureV2 原来依次 ListByFilter、全状态 ListByFilter、ListVaults，重复认证并可能取得三个时刻的数据。新增 ListDesktopSnapshot 从一次认证事务生成三份元数据；仍按原顺序追加筛选 list/search、item.list、vault.list 三条已知签名审计事件，保持查询 HMAC、完整链验证、拒绝路径及 UI query/ABA 守卫，无明文/秘密缓存或协议扩权。

## Firefox 实际失败与回归

首版 PR #60 的 Web CI 在 Firefox 原生旅程失败，其余五项通过；该 head 未合并。实际桌面诊断发现弹窗初始 innerWidth=0，body 的 max-width:100vw 将固有 390px 宽度夹为 0。保留固有宽度，仅在 320–389px 的正视口适配；加载真实 CSS 的零宽 iframe 负控在旧源码失败。驱动同时按扩展拥有的精确 popup URL、可见且非零视图/宿主唯一性拒绝歧义；背景 RDP 与 WebDriver Chrome 两个 realm 分开，滚动后两次稳定几何采样才允许一次物理点击。两个隔离 VM realm 的驱动回归覆盖隐藏/折叠/零宽/外来 URL/多匹配，保留导航、锁定、原生拒绝、OTP 与隐私断言。iframe 证明 CSS 尺寸，不单独证明 Firefox 宿主自动恢复；完整原生运行及最终六项 CI 单独记账。
