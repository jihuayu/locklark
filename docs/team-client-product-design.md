# 团队客户端的下一批实现边界

> 当前状态补记（2026-11-07）：团队身份、bootstrap、发布与恢复等协调层已有实现并合入 `main` `4abecb8`；本文保留设计约束，开头“尚未实现”描述的是当时阶段，不能解释为当前所有协议/协调代码都缺失。完整原生团队 UI、邀请/草稿冲突及移动产品闭环仍需按实际入口和验收逐项对账。

这是主代理在团队同步协议之外制定的产品设计，尚未实现或验收。现有 `directory` 和 `teamsync` 已提供签名历史、双钥持有证明、完整快照重加密、远端读取、精确父版本发布与未知结果对账；这些接口不能代替实际的创建团队、设备加入、查看条目和撤销操作。

## 首个用户闭环

首批交付可信桌面上的团队创建、设备加入、同步后按次查看，以及 owner 撤销设备。使用 MyGo 原生界面；浏览器继续只接收有限元数据。团队编辑、离线草稿与冲突处理随后接入同一会话，移动端再绑定窄接口；没有完成这些后续流程之前，不宣称完整团队产品已完成。

首个闭环必须使用独立的真实服务进程、TLS、实际系统密钥服务、两份设备身份和实际加密快照。验收夹具可以布置这些资源，产品不能依赖夹具生成配置或私钥。

第一批创建流程只配置一个 pinned owner。该管理端分别持有 owner 与 publisher 的独立系统保护密钥，并作为普通设备入网取得解密资格；成员和设备可以有多个。只有同时持有这两个管理角色、并有活动解密设备的端才能发布 roster 变更。设备获准入网不会获得 owner 或 publisher 私钥，也不能因此显示管理权限。协议允许多个 owner 公钥，不代表产品已经实现 publisher 权限的跨管理端分配；该分配必须另行设计和验收，不能通过普通私钥导出或悄悄复制设备身份补齐。

所有已入网设备都能解开整份团队快照，`reader` 只限制发布，不提供逐条读取 ACL。撤销只排除后续快照和请求，不能收回此前保存的明文或旧密文及相应解密能力。

## 身份和本地存储

- 新增独立 `teamclient` 协调层。它不复用个人库的 Device、Signing、Audit 私钥或快捷解锁 capsule，也不把团队私钥塞进普通登录、笔记或文档条目。普通显示、JSON、KDBX 导出和个人库备份不能复制团队设备身份。
- 每个安装配置生成独立随机设备 ID、age 解密身份和 Ed25519 签名种子。owner、publisher、sequencer 各有独立 Ed25519 密钥；owner 身份本身没有快照解密权，owner 的设备须正常入网才能读取并重新加密数据。
- 私钥由系统密钥管理接口保存。使用独立用途域、随机配置 ID 和角色派生存储 ID；保护内容绑定版本、配置 ID、安装 ID、scope、角色及其公钥。加载后重新派生并比对全部公钥。不能把个人快捷解锁的24小时身份格式当作团队身份格式。
- OS 存储不可用或拒绝认证时，操作失败；没有普通文件、环境变量或命令行私钥回退。Linux 的 Secret Service 可能在已解锁时不再次提示，不能称为逐次生物识别。Windows/macOS 的成功路径须分别实际验证。软件 age/Ed25519 私钥在授权会话内会进入应用内存，不宣称其硬件不可导出。
- 公开配置和密文缓存放在本机私有目录，包含固定 pins、端点、可信证书策略与状态版本。检查点使用既有独立 `AnchorStore`，不纳入缓存或个人备份。删除/回滚缓存不能重置检查点；缺失检查点不得从服务器或缓存悄悄重建。
- 配置创建、OS 密钥写入、签名发布不能跨存储假装原子。显式保留 preparing、pending、active、unknown 状态；只有已验证的精确回执与检查点持久化成功才能进入 active。恢复只对账原操作，不能重新生成身份或重签后自动重试。
- 首批不提供团队私钥导出或复制设备。设备遗失通过另一个 owner 批准新设备并撤销旧设备恢复访问；owner 灾难恢复与独立加密备份另有实现和验收要求，不能把未实现的恢复能力写进产品承诺。

## 创建与服务初始化

服务端先通过显式本机操作生成并系统保护 sequencer 身份，只输出其公钥与公开初始化材料。owner 从可信渠道独立确认该公钥；不能把刚连接的服务自报身份当作信任根。

桌面创建 owner、publisher 和首个设备的独立身份，使用 `NewConfigWithWriterACL`，对 Genesis 上的首设备完成 `IssueChallenge`、`AnswerChallenge` 和 `VerifyAdmission`，然后 `Build` 初始成员及快照。首个 owner 设备也没有免证明通道。

桌面导出的初始化材料只包含 pins、签名 proposal 与密文 snapshot。服务新增明确的初始化入口，核对其已保护的 sequencer 公钥与 pins 一致后使用 `directory.Create`，并建立独立服务检查点；不能覆盖既有目录或检查点。既有隐藏终端 sequencer 输入只保留兼容用途，新产品流程不要求复制私钥。

桌面在 TLS 校验、固定 pins、完整历史及独立客户端检查点全部通过后才显示团队可用。HTTP 不新增“相信服务器返回的配置”入口。

初始创建与已有团队入网使用不同的检查点规则。Genesis 只用于明确的新 scope 创建。新加入设备须从已经持有独立检查点的 owner，通过经独立指纹核对的可信入网交换取得精确 checkpoint；不能从服务器、缓存或通用默认值初始化。该 checkpoint 与 scope、成员、设备双公钥一起成为独立 expected enrollment，不能直接复制未核对 challenge 的字段。首次检查点创建采用明确的一次性、不覆盖写入；已有记录必须精确匹配或通过正常历史推进，缺失的既有 anchor 不得重新初始化。

首次初始化前须持久记录本机创建意图，绑定 scope、初始 proposal 摘要及尚未完成的阶段。服务目录创建与独立 anchor 创建分步完成，发布服务在两者完成前不可用。部分成功后只能对账这个原始创建意图及可信初始化材料，核对确切的初始 receipt，再显式完成尚未进行的步骤；不能重新签名、覆盖既有文件，或从数据库头部自行宣布一个检查点。已激活服务的 anchor 丢失直接拒绝服务；无法证明仍处于首次创建阶段时也拒绝。该持久协调与恢复入口必须实际实现后，才能称 bootstrap 闭环完成。

普通 profile 可被恢复到旧版本，因此其中的阶段标记不能单独授权重新初始化。服务身份的系统保护记录必须从 `unbound` 一次转换为 `bound`，绑定完整 pins、scope、原 artifact 摘要及原始 profile、目录和 anchor 路径。转换只能在正向加载并核验原 `unbound` 身份后进行；加载错误不代表记录不存在。独立身份租约覆盖该转换，复制 profile 到其他路径不能获得新转换资格。

为避免旧 profile 重建既有检查点，owner 的 Genesis anchor 在首次准备配置时创建，后续流程只允许打开。服务则在首次身份绑定之前创建精确 Genesis anchor；只有本次实际完成新绑定的 worker 可以调用 `directory.Create`，并将 anchor 推进到初始回执。任何启动时已加载到 `bound` 身份的入口，只能核对既有目录和既有 anchor，不能依据旧 profile 的标记创建其中任一文件。绑定后、目录创建前发生中断且目录缺失时，保守保留 unknown，不自动重签或重建。这个边界抵御普通配置回滚，不声称能抵御系统密钥库与全部本机状态同时被恶意回滚。

owner 也不能仅靠公开 outbox 的标记防止重新签名。其系统保护记录须从 `unbuilt` 转为绑定操作 ID 的 `claimed`，且只有本次实际完成该转换的 worker 才能生成初始证明与签名材料。保存原始规范 artifact 后，再转换为绑定同一操作 ID 和 artifact 摘要的 `built`，才允许导出。恢复只能加载系统记录并比对原 outbox；即使 anchor 仍是 Genesis，公开配置回滚也不能获得另一次生成许可。`claimed` 后丢失原材料、或无法确认最终转换时保持 unknown，不盲目重写系统记录或重签。配置状态查询只显示未经重新验证的本地记录，不代表系统授权或远端新鲜状态。

## 加入与撤销

待加入设备本地生成身份并展示公钥摘要；owner 从可信渠道核对设备与成员。请求、challenge、response 和最终确认分别显示 scope、成员、设备 ID、双公钥及精确 parent，不能盲目从收到的 challenge 复制 expected enrollment。

现有 challenge 不包含角色或时间期限：角色由 owner 签名 roster 授予，parent 变化使 challenge 失效。首批界面必须准确表达这一点，不称为“带过期时间且已同意角色的邀请”。如果后续需要此语义，应增加有版本的签名协议并明确降级拒绝，不能只在 UI 加一个计时器。

owner 提交加入或撤销前获取并验证当前状态，由其活动设备解密完整快照，使用新 roster 完整重加密并 `Build` / `Publish`。不能只修改成员 JSON。撤销最后一个可读设备走明确的冻结流程，不声称冻结后能凭 owner 签名身份恢复已丢失的明文。

发布结果丢失或检查点更新失败进入 unknown。`Reconcile` 只能确认精确 proposal 已提交、同代不同 proposal 冲突，或仍未知；原 parent 未变化不代表可以安全重试。永久设备和公钥墓碑保持有效。撤销不收回设备此前已得到的明文。

发布前必须先持久保存精确 proposal、密文 snapshot、parent/checkpoint、操作 ID 与 pending 状态，成功刷盘后才允许 POST。重启后只能加载并验证这条记录，对账原 proposal；内存中的 unknown 标签不足以支持恢复。结果记录与 anchor 推进也可能部分成功，应保留原操作直至二者一致，不因丢失回执生成新 proposal 或重置 parent。

owner、publisher 和 sequencer 公钥都是不可变的 scope pins；owner 策略是 1-of-N，不是多签门槛。当前协议没有原位新增/移除 owner 或角色密钥轮换。丢失全部 owner 密钥、publisher 或 sequencer 密钥，或者这些角色已失陷时，不能通过替换配置继续旧 scope；恢复需要独立可信备份或明确的新 scope、重新核对 pins 与设备入网。新 scope 不能被描述为原历史的无缝续接。完整角色灾难恢复、备份和迁移仍是后续实现范围。

## 会话、显示和验收

`TeamSession` 拥有密钥、网络取消、固定操作代次和空闲期限。锁定首先同步失效代次并取消在途请求，再清理密钥及待显示内容；迟到的 OS 认证、网络响应和解密结果都不能复活会话。

列表只返回稳定条目 ID、revision 和有限元数据。按次显示绑定 scope、精确检查点、条目 ID/revision、字段、会话代次和原始期限；取值前核对新鲜远端状态与检查点，解密后再次核对授权点。离线或无法证明新鲜时显示明确状态，首批不提供离线秘密披露。一次新鲜响应只证明该请求期间服务观察的状态，不能保证交付后没有并发撤销。

验收包括真实 bootstrap、两设备加入、双钥不匹配、错 pins、错误角色、旧 parent、缓存回滚、缺失检查点、撤销后重新读取、锁定与迟到回调、OS 拒绝、未知发布对账，以及整个日志/网络/公开配置中的秘密 canary。父代理独立验收与 Luna 审阅之后才扩大到 writer 草稿冲突和移动配对。
