# Locklark 开发进度

总规格与验收矩阵见 [design.md](design.md)。下表按依赖列出持续目标；只有实际跑过的范围才写为已验证。「待做」包括本机仍可开发的部分；只有需要外部条件的那条验收延后。

| 工作 | 已验证 | 下一项可开发、可验收的增量 |
| --- | --- | --- |
| 持库核心与兼容 | Go 双密钥样本向量、独立设备收钥、吊销后离线解密失败；合成 1PUX 改名、TOTP、附件和迁出对账 | Argon2id 文件互操作；更多原生字段类型；真实迁移前做恢复演练 |
| 审计 | 演练签名快照内按 session 找回拒绝；常见凭据形态在新请求写盘前拒收 | 每设备独立审计签名、前序摘要、异地检查点；删节、回放与损坏负测 |
| 成员、同步与恢复 | 同账号及多设备的文件级撤销；未实现团队目录或备份服务 | 签名成员目录和可信新鲜度；独立离线恢复材料，灾后新设备身份与新代次 |
| 远程授权 | 本地加密待办、按 session 分页查询 | 认证提交者、持久批准/拒绝、超时与一次性兑现；AI 只能否决 |
| 桌面、浏览器和移动 | 只有 CLI 演练 | MyGo 原生托盘、系统解锁、搜索和审批；浏览器、iOS/Android 客户端和真机验收 |
| 网关与 Web | 已定 Go 宿主、Bun 插件、Next.js 管理界面 | 无凭据的插件 IPC、具名工具、宿主注入和 OS 隔离负测；Web 不得参与解密 |
| 机器授权 | 已定 invoke 与 deliver 独立部署 | 分别签发/吊销、固定上游及交付对象，串用凭据的负测 |

当前实现均为合成预览。托管 CI 受 GitHub 账户额度影响，开发继续使用本地 Windows/WSL 验收。正式使用还需要独立安全评审、干净机器恢复、移动真机与逐平台 1Password 行为对照。
