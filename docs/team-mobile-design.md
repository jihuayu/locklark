# 团队远端同步与原生移动端

从已合并 PR #31 的 main `9d8d57475f3fb904fc9fe4bedc0c1e6b4ce07535` 接续。用户要求持续完成团队同步与移动端；主代理负责架构、功能设计和独立验收，Sol xhigh 子代理实现团队网络协议、共享移动核心、Android 和 iOS，Luna max 独立审阅。下列是实现与验收约定，不代表已经交付。

## 信任边界与同步

1. 继续使用现有 WriterACL + 双钥持有证明目录策略，不隐式升级旧 scope、丢弃撤销墓碑或改变 owner/publisher/sequencer 分权。个人库与团队库分离，不能把个人库上传到团队。每个团队活动设备可读取整份团队快照；reader/writer 区分写权限，不提供逐条读取 ACL。
2. 可信排序端只有 sequencer 私钥、签名目录历史和加密快照。客户端独立提供 pins、HTTPS 地址、可信证书根及检查点，不接受服务器自报信任根。TLS 1.3、主机名校验、禁止重定向和隐式环境代理；请求与响应均有明确容量和时限。普通中继不能替代可信排序端。
3. 设备请求签名绑定 scope、身份类别、设备 ID、操作、新生成的32字节随机 nonce、检查点及正文摘要。owner 客户端是独立的显式身份，以 pinned owner 签名验证，可处理冻结读取、撤销和恢复；设备不能冒充 owner。写请求必须同时满足现有 proposal 权限与精确 parent CAS，不能把一次新鲜读取当成以后可写的租约。
4. 排序端在权威数据库的一次读取中验证并导出完整历史和当前密文，响应签名绑定请求摘要、nonce、精确 head 和完整响应摘要。客户端复用同一历史验证器，重验签名、持有证明、前态权限、永久墓碑、父链和当前快照，再核对独立检查点。32 MiB 网络响应、16 MiB 发布请求和8 KiB读取请求为明确容量限制，超限拒绝，绝不截断历史。新鲜性只表示本次请求期间排序端观察到的状态，默认15秒单调时钟期限；不能承诺收到响应后没有新的并发撤销，也不抵御可信排序端本身作恶/分叉。
5. 客户端检查点通过独立 AnchorStore.Load/Advance(expected,next) 持久 CAS 更新；缓存不是信任根，持久化失败不能返回“同步成功”。排序端也必须独立持久保存最后确认的 head，启动不能因该文件缺失而自动从数据库重建。响应成功前更新排序端检查点；目录提交成功而检查点更新失败时结果未知。下次读取只能在完整验证后把检查点推进到数据库已有后代，数据库落后于服务端检查点则拒绝服务，即使请求者只知道较早状态。单独恢复旧目录数据库不能让服务端重新签出“当前”；整个服务与其独立检查点同时回滚或失陷仍需外部见证，不能由 nonce 解决。离线缓存不能标记为最新；没有可信新鲜状态时编辑只允许成为本机草稿，不能向旧代次发布。该草稿与冲突产品闭环仍须实际实现后才能宣称完成。
6. 发布不自动重试或重签。回执丢失显示未知，显式读取完整历史对账：找到精确 proposal 可确认已提交，同一代存在不同 proposal 可确认冲突；head 仍为原 parent 时原请求可能仍在提交，必须保留未知。并发改同一父版本只接受一个，不能按服务器时间覆盖另一份内容。
7. 服务端入口使用本地公开配置与常规 TLS 证书，sequencer 私钥仅通过隐藏终端输入或独立系统保护入口提供，不接受命令行、环境变量或普通私钥配置文件。服务端不接收条目明文、设备私钥、owner/publisher 私钥。公开元数据也不能自动进入访问日志。

## 移动端核心和原生应用

- Android 使用 Kotlin 原生界面，iOS 使用 Swift 原生界面；通过 gomobile 绑定有限 Go 接口复用现有个人库的双因素、事务、审计、生成器和 TOTP，不复制一套密码协议、不使用 WebView 处理秘密、不用假仓库冒充真实金库。
- 首个实际闭环包括创建、完整解锁、标题搜索、列表、新建/生成登录、按稳定 ID/修订编辑、按次显示密码/TOTP、主动及后台锁定。创建时明确保存新 Secret Key；因素不落盘、不进入日志。无完整因素不能注册快捷解锁。
- 移动门面只暴露有限 metadata Row、精确修改 API 和显式 SecretValue；不提供普通 JSON 全条目读取。SecretValue 一次性取值、最多15秒并受 OTP 原窗口限制、绑定会话和操作代次。取值可能进行磁盘重验证，应在工作线程执行；主线程展示前再核对前台代次、目标 ID/修订、会话与时间边界。生命周期锁定必须立即失效旧代次，清空界面和草稿，再异步完成磁盘相关清理；迟到解锁/取值/保存不能复活旧页面。
- UI 在排队之前同步调用 CaptureOperation，取得共享金库状态、但固定当前代次的操作视图；工作闭包只能使用该视图。核心在取得串行锁后再次核对代次，不能把原生前置检查当作原子授权。旧视图不能续成新视图，基础 Vault 只供生命周期控制；新操作必须等待旧锁清理完成。OTP 最终交付在同一短授权点复核原 OTPBounds，并把最近通过的时间样本交给原生界面，防止同周期内回拨。
- 第一批复用既有 native 签名审计事件命名空间，其中部分名字仍为 `desktop.*`；不据此宣称可独立证明“来自手机”。增加独立移动来源事件需要后续明确的审计协议升级，不能仅改显示标签冒充签名证据。
- 系统快捷解锁沿用完整解锁后固定24小时的身份 capsule，绑定路径与密钥槽，不保存主密码或 Secret Key、不续期。Android Keystore 使用需用户验证的随机 AES-GCM 包装钥匙与 no-backup 密文；iOS Keychain 使用 WhenPasscodeSetThisDeviceOnly 和 userPresence。没有系统保护或验证失败时回到完整因素，不降级为明文文件或普通偏好存储。不能把软件 age/X25519、Ed25519 私钥称为硬件内不可导出密钥。
- 自有系统认证弹窗不得通过忽略所有非活动事件来维持解锁。iOS 设计为先在完全锁定且遮挡的状态预认证，仅保留非秘密的认证尝试标识；真正进入后台立即取消该尝试和 LAContext。成功后必须回到活动状态、同一尝试、短单调时限内并完成锁清理，再用原 LAContext 读取 Keychain，禁止再次弹窗；任何失配均回到完整因素。系统认证成功路径需独立运行证据，不能由无设备认证时的拒绝测试代替。
- 金库及 sidecar 排除系统云备份，iOS 完整文件保护；Android 敏感窗口禁止截图，iOS 非活动状态及时遮挡。托管字符串、系统键盘和设备截图机制的限制须如实记录，不能承诺物理擦除。
- 团队设备身份每次安装独立生成并由已有可信端批准；完整因素不能恢复已撤销设备资格。个人快捷解锁身份与团队设备/owner 身份分开，禁止把个人库身份 capsule 当作团队邀请凭据。

## 持续交付与验收

先保存实际行为失败，再实现与复核。团队验收使用真实 TLS、签名、bbolt、age 和 KDBX，覆盖双设备数据读写、reader 越权、设备/成员撤销、旧父、降级、篡改、回滚、重放、固定信任根、并发单赢家、回执丢失和检查点存储失败；完整输出及网络请求不得出现合成原值。移动核心以实际加密文件验证重开、错误因素、编辑冲突、取消/后台锁定、过期/回拨和敏感返回值生命周期；平台应用必须实际编译并尽可能跑模拟器，不能以文本扫描代替构建。

主代理独立运行固定构建的端到端验收，Luna review 与子代理本地通过均不替代该步骤。精确 head CI、正常 PR 合并后接续下一批。原生系统填充、Credential Manager/AuthenticationServices、Passkey、附件/历史、完整团队邀请/草稿冲突 UI、远程审批、两部真机和逐平台系统钥匙验收仍是总目标；没有实现和证据前不得标记完成。Linux 云端没有 KVM、Xcode 或手机硬件，下载 SDK、macOS CI 与软件模拟器可用于相应自动检查，不能替代真实生物识别和设备失效场景。
