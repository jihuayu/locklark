# 浏览器显式保存与更新：架构与验收约定

主代理设计及独立验收；Sol xhigh 实现；Luna max 独立审阅。PR #26 精确 head `6c649d992f913c36a75a16f30e1320c4b008d085` 的四项 CI（run `42073803355`）通过，已合入 main `0f38177eb1059121d04e94fb96d264126688573f`；本切片从该实际主线的 `codex/browser-save-update` 开始。本文件是约定，不代表实现或验收已经完成。

## 用户流程

保持既有原生解锁/系统快捷解锁与配对流程。当前 HTTPS 网站弹窗提供“保存当前登录”，并在精确网站候选旁提供“更新此登录”。仅真实扩展 popup 显式操作触发；不安装页面监听器、不监测提交、不自动保存、不自动提交网站表单。用户若使用 Firefox，从工具栏打开扩展，快捷键可自行配置。

扩展背景进程按真实 tab/documentId 捕获同一顶层文档的明确用户名/密码输入对；页面来源、可见性、可用性、同一表单与所有关联提交按钮的同源约束与填充一致。无歧义、不支持页面明确拒绝。捕获阶段有短期限及代次约束，后台API挂起、切页、切标签、断开或锁定不得发送迟到捕获。不在弹窗、日志、storage、页面消息中传值。

新建：原生窗口显示精确来源及“新建登录”，默认标题使用来源（不信任网页标题），允许在原生界面改标题。更新：原生显示精确来源、现有条目标题/ID/修订，明确仅替换用户名和密码、保留标题/URL/OTP/关联与来源记录。任何新建/更新必须逐次原生批准；原生拒绝/取消无金库变更。密码始终掩码，不在待办元数据中公开。保存的是用户点击时捕获的值，不声称验证网站账号正确。

## 协议及事务

仍使用固定扩展 Native Messaging 与已有15分钟连接能力，待确认最多30秒、一个待办、每请求随机ID。为有界输入增加明确save-new/save-update消息形状，未知/重复键和不适用字段拒绝。每字段UTF-8上限16KiB；按最坏JSON转义预算选择严格总帧限额，不因增加字段放开无界读取。其他请求不能带秘密字段。消息/待办String/JSON默认脱敏，明确传输编码路径外不序列化秘密。

个人核心新增受控浏览器保存事务，不拼接AddLogin与Edit(url)或两次字段Edit。新建在同一认证事务内生成ID、写username/password/精确origin URL并审计；更新在同一事务内核对active/login、精确revision、来源，再一次替换两个字段并审计。审计与快照原子提交，重读历史能够验证新动作与修订。审计只含动作、ID、修订及用途分离HMAC上下文绑定，不含username/password/原始来源。失败/提交错误无部分条目或单字段变更。

批准的线性化点必须同时约束连接能力/取消代次/会话锁定及事务执行。及时到达的合法取消在该点前拒绝；提交后取消不能撤回已保存的条目，UI和文档明确边界。协议只返回ID/修订等元数据回执，无字段回流。断管/提交后回执丢失显示结果未知，绝不自动重试；用户可以重开原生金库核实。重放同一请求ID不得二次写入。

所有临时值在拒绝、过期、锁定、断线、提交完成及错误路径释放；承认JS/Go不可变string及浏览器IPC的内存清除限制，不声称物理擦除。Next.js管理页和普通Agent接口继续无原值访问。

## 验收约定

先红：个人事务原子新增/更新、错误来源/修订/状态、提交失败、拒绝/锁定/过期/重放、审计重开和无原值扫描；协议严格消息与有界字段；扩展仅popup sender、静态采集/真实documentId、迟到与切页、无秘密状态/日志。

真实Chrome及Firefox受控HTTPS+隔离合成库+实际MyGo外部控件输入：新建、随后填充验证；更新、随后填充新值且ID不变；拒绝/导航/锁定后库不变。真实GUI通过AT-SPI标签+XTest，无产品审批测试开关；私有诊断、只截匹配窗口、不回显远端异常。Luna review、主代理独立验收及精确head CI全部通过后PR合入。

不以该切片关闭自动检测复杂站点、TOTP、Passkey、Safari/移动、完整迁移或系统硬件验收。

## 架构预审结论与冻结决定

Luna/max 已预审，无架构阻塞，以下补充为实现硬约束。

1. 原生批准不立即提交。Host 对该待办产生 CSPRNG nonce，绑定连接能力、requestID、代次、操作和短期限（至多3秒且不超过原待办/能力期限），发送无值的 save-ready。后台只为仍live的同一待办处理挑战，在有界期限内重查活动窗口/tab/URL origin，并对原documentId作无副作用probe，返回一次commit-ready。宿主恒时比对nonce并一次性消费；新消息也有自己的防重放ID，显式引用原请求ID。未知nonce/错误capability/过期或重放不能取消新请求。
2. 使用每请求 pending→commit-won / pending→cancel-won 的原子仲裁。合法cancel、锁库、能力/请求/挑战到期、断线与事务写入前检查竞争同一gate。Session.RequestLock也参与，不能只在事务前各读一次bool。短仲裁锁不得等待数据库或管道；事务内认证/状态/来源/修订复验后、第一次变更前是写入gate的线性化点；随机ID生成、HMAC及所有可预见校验先完成。gate前取消获胜无写入，gate后不能撤回，回执丢失/取消/错误显示未知且不自动重试。
3. 文档精确声明：握手证明扩展收到挑战后最近一次观察的文档身份和消息到达顺序；不证明DB commit瞬间浏览器物理上仍展示该页面。网站JS也可能自行发网请求，同源表单检查不是网络隔离保证。
4. 总输入帧256KiB，每个username/password UTF-8字节不超过16KiB，其他字段独立严格限额。缺字段与空值区分；username可空，password沿用现有规则非空。revision沿用现有审计hash作不透明CAS，不引入数字版本。新建返回的revision也必须是实际已提交审计事件关联的修订。
5. Host Pending/View只暴露元数据，秘密单独私有payload持有。非法消息打印不泄露；测试故意构造含合成值异常验证所有输出路径。关闭失败不得发成功回执，历史审计重读规则同步支持两个新动作。

6. 冻结两次RPC：save-new/update的response是save-ready（id=原id、nonce），随后commit-ready有独立新消息ID、引用原request_id+nonce，其response为saved元数据。后台在最初post前生成并保存原request_id；两次RPC分别有有限等待及终态，不给同call重复resolve。save专用window_id参与context/DTO/HMAC，旧fill wire不必改。
7. 保存取消使用独立cancel-save并显式绑定原request_id；旧的无目标cancel不能取消新save。只有cancel-won可报告cancelled；commit-won后取消或Session后置active检查/commit/close/pipe失败一律保留unknown可能性。每次RPC新id受seen防重放保护。
8. UTF-8字段限额按TextEncoder字节计；采集先拒绝未配对UTF-16 surrogate。Go保存输入采用严格raw JSON UTF-8和Unicode转义对校验，拒绝encoding/json默认有损替换，不静默改变凭据。维持直观username/password DTO，不使用base64重新定义整个协议。

9. 保留已认证业务拒绝审计。Gate含义是开始持久化本请求结果，而非commit-won代表已保存。slot/历史认证失败或格式非法无可信审计条件则回滚；已认证的来源/修订/状态/不存在业务拒绝也在同一事务中争gate，cancel-won无任何写，commit-won只记严格拒绝事件、不改snapshot/item/revision。只有事务与close成功才返回明确拒绝，gate后不明错误仍unknown。成功分支一次写snapshot+成功审计，不引入额外事务。

## 独立验收矩阵

| 观察点 | 必须成立 |
| --- | --- |
| 捕获之前 | 只有扩展真实 popup 能触发；仅请求当前活动窗口的顶层文档；隐藏/只读/歧义/跨源表单不取值 |
| 原生批准之前 | 金库没有新增/更新；popup/state/诊断中没有捕获值；请求只在私有内存短暂持有 |
| 原生批准之后、最终复核之前 | UI显示等待页面复核，不宣称保存成功；导航/标签切换/断线/锁库取消并清值 |
| 新建成功 | 一次事务产生新ID、实际修订、canonical origin URL及完整字段对；重新打开和实际填充一致 |
| 更新成功 | 同ID、修订变化、两字段一起更新；标题/URL/OTP/附件关联/导入来源等其他字段保留 |
| 已认证业务拒绝 | 仅拒绝审计增长，条目/快照/修订不变；事件重开与验证通过 |
| 取消先赢 | 包括拒绝事件在内的任何写入均未发生；旧目标取消不得影响新请求 |
| gate先赢后故障 | 回滚、close、断管、迟到锁库等不误报确定未写；不会自动重试；可由原生金库核实 |
| 原始凭据 | UTF-8字节边界、孤surrogate、转义膨胀、缺字段/空用户名/空密码均有明确测试；不静默改值 |
| 协议终态 | nonce单次且短期、能力/请求/窗口绑定、两次RPC各自终态、迟到消息不覆盖新状态 |

外部验收观察库时，从原库的只读 bbolt 事务导出一致快照到私有副本，在副本认证并核对条目/修订及保存事件数；不在原库调用会新增观察审计的List/Audit，也不把正常匹配审计误判为保存条目。不得并发裸复制正在写的数据库。测试只能使用合成库，报告只输出布尔与必要元数据。

10. 格式正确的重复消息ID固定拒绝，不重放操作、不主动清除新待办；旧commit-ready/cancel-save不能借协议断连路径误伤新save。所有收到的消息（含重复/错误能力）仍计入独立总预算，畸形帧/DTO、预算耗尽或实际断管继续关闭连接。这不是对同一peer无限资源滥用的可用性承诺；后台仍拒绝未知/违规宿主响应，合法迟到RPC按原call/retired ID处理。

11. Popup 的刷新/业务请求在派发前同步禁用旧候选及保存操作，直到最终状态可用；断开可以中断挂起动作。动作代次与响应序号阻止旧成功、失败或收尾覆盖新状态。候选 DOM 中 ID/修订与事件处理器使用同一元数据；未变化的轮询不重建按钮，保持键盘焦点。保存未知状态由后台锁存，导航、锁库、断开和迟到响应不能误称未保存。
