# 个人引用目录与受控披露

基线为 PR #4 合并后的 main `55b3ae7ab9b2d819a8cb7269455fb48778d40a5f`；工作分支 `codex/personal-references`。实现提交、最终检查链接和独立复核结论记录在 PR 正文。

## 认证和事务

`personal references` 在双因素认证、快照验签、完整账本与历史验证后投影个人 v1 元数据，并在同一事务写入 `reference.list`。库 ID 来自已认证账户槽的 16 字节 account，固定别名为 `Personal`。目录只含库身份、条目 ID/标题/修订和三个固定字段的引用；空用户名或未配置 OTP 仍有相同字段身份。目录不是访问许可或配置状态。

`reveal-ref` 和 `otp-ref` 在同一 Update 回调内认证输入来源、投影、Resolve、精确 Bind 和比较调用者修订，再走既有受控披露流程。仅文本/username 和密码/password 可原值披露；OTP/otp 仅可走提交后计算验证码的入口。raw OTP、错误类型、旧修订均拒绝。成功审计只有解析后的稳定条目 ID、当前修订和既有披露动作，不保存引用文本或名称。事务提交且数据库关闭后才写终端，OTP 沿用时钟/窗口检查。

可认证的引用拒绝记 `reference.reject`，结果限定 `not-found`、`ambiguous`、`wrong-type`、`stale`；不保存调用者引用、修订、条目或标题。语法错误、错误因素和不合法的完整目录不产生成功事件；元数据投影失败返回零目录，绝不返回部分条目。备份/恢复验证并保留新的查询和拒绝事件。

## 使用范围

真实 CLI 必须有交互 stdin/stderr、双因素和 SHOW 确认；值只在 stderr 中显示为转义 JSON 字符串，stdout 为既有无值回执（OTP 多有效窗口）。这不阻挡同用户操控 PTY，也不保证终端历史清除。引用可能暴露标题/身份，因此参数本身应只含非秘密标识。

名称/ID 大小写不敏感且必须唯一；名称恰等于别人的 ID 也拒绝，绝不优先猜 ID。语法仅支持既有 ASCII 子集，无查询属性/百分号编码；中文标题可用 ID。目录拒绝超过 1024 字节或含控制/Unicode 格式字符的名称，可用直接 ID 操作修正。恢复新账户产生新库 ID，旧 canonical 引用不再找到目标；即使使用别名，也必须换新修订。当前个人布局无区段，不提供文件附件或原始 OTP 取值。

## 失败先行与验证

先运行新增引用测试，由缺失 References/RevealReference/引用请求接口导致编译失败，日志 `/tmp/locklark-validation/personal-reference-red.log`。实现后覆盖：

- 真实加密库目录无字段值；规范 ID 引用、别名/大小写；写终端时另一事务可看到已提交的稳定字段意图，条目修订不变。
- 重名、名称冒充 ID、不存在目标、错误类型、旧修订与错库，拒绝事件只含固定类别；直接 ID 路径保持可用。
- 错误因素、事务完成后回滚、非法目录均零输出/零成功回执；整份目录失败不返回部分结果。
- 并发改密只能读取指定旧修订或拒绝；备份/恢复验证旧拒绝历史，旧库引用与旧修订拒绝，新引用能读到恢复后的实际值。
- 真实 PTY/ConPTY 的确认/取消、错误因素、目录、密码与 OTP、歧义/类型/版本拒绝；Python 独立 HMAC 校验验证码；审计没有引用选择器或字段值。

全仓 Go（含 Bun/PyKeePass）、引用/披露/OTP 定向 race、静态检查、终端驱动与全部已有 CLI/MCP 验收、macOS arm64 交叉编译，以及 Luna/max 独立复核和最终双平台 CI 均按实际结果在 PR 记录。这里没有新增通用导入、run/inject、团队/Agent 披露授权或真实 op 对照；外部密码评审、原生 macOS/移动设备和硬件故障仍待独立验收。

Luna/max 独立复核发现 Unicode Cf 标题可造成终端显示欺骗；新增元数据及真实库回归先在旧实现失败（`reference-format-red.log`），随后在共享目录校验中拒绝控制和格式字符，并增加 PTY 拒绝及直接 ID 可用回归。最终验证与复核结果见 PR #5。
