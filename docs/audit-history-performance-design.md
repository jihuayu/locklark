# 已验证审计前缀复用

对应 [issue #35](https://github.com/jihuayu/locklark/issues/35)。目标是在长期使用的库中减少交互操作反复进行的 AEAD、JSON 和 Ed25519 工作，保留现有完整历史、恢复链、快照及修订校验。存储格式、协议和回滚威胁模型不变，不增加持久化 checkpoint 或未签名索引。

每次认证仍读取并检查当前 slot、会话权限、签名快照和加密 tip；按顺序遍历所有事件，哈希 `domain || sequence(8 bytes) || raw length(8 bytes) || raw ciphertext`。序号必须连续，不能有嵌套 bucket、空值、超限记录或超出 tip 的事件。归档也逐字节计算密文摘要。因此修改中间事件，即使最后事件和 tip 未变，也不能命中旧前缀。

Session 仅保存一个不可变验证记录：身份绑定、已验证前缀长度/摘要、末尾事件哈希、origin、修订表，以及已验证归档密文摘要和 anchor。命中后复制修订表，用与冷路径相同的事件校验和回放规则验证新增尾部，最后再次匹配 tip.Last。前缀、origin 或长度不兼容则回到完整验证；当前快照、条目 schema/修订映射及 vault 元数据始终重新验证。新的合法签名快照不会阻止对相同历史前缀的复用。

候选缓存只在事务成功提交或只读操作成功后发布。写命令发布的是已经认证的提交前前缀，可能落后若干新事件；下一次读取重新检查全部密文并验证新增尾部，不把刚写出的整个历史直接标记为可信。失败提交和回滚不发布新候选；外部 writer 的合法新增事件也走同一尾部验证。

正常操作只有在归档完整密文摘要和已认证 origin anchor 均相同时，才复用此前的归档验证结果。`audit.list`、`audit.archived`、`backup.prepare` 一律完整验证并返回全部历史/恢复链，不能返回截短的审计结果。缓存不保存事件正文、恢复链、条目、密码或密钥；传出的修订表不与缓存共享可变 map。完整锁库清除缓存，RequestLock 标志拒绝新操作和迟到发布。

哈希仍然与历史字节数线性相关，快照解密也仍有成本；本改动不声称常数时间读取、不改变历史增长，也不新增防止完整合法旧库回滚的保证。
