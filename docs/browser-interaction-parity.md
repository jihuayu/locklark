# 浏览器交互完整度与 1Password 对齐

日期：2026-11-10。本文件记录本轮交互补齐：键盘路径、焦点管理、破坏性操作确认、加载/空状态和动画降级。目标是让已有功能在操作习惯上接近 1Password 扩展，而不是新增功能。参考行为来自 1Password 扩展的公开交互与 [beta 静态对照](browser-1password-beta-parity.md)，没有在真实 1Password 界面上逐项并排验证。

## 已完成的交互

### 金库列表与详情

| 交互 | 行为 |
| --- | --- |
| 列表键盘 | 焦点在条目上时 `↑`/`↓` 移动，`Home`/`End` 跳到首/尾；`Enter`/空格打开条目（原生按钮语义） |
| 搜索 | 搜索框 `↓` 进入第一条；`Esc` 清空；任意非输入状态下按 `/` 聚焦搜索 |
| 详情返回 | 详情页 `Esc` 或“返回”回到金库，并把焦点还给打开前的条目；条目已不在当前筛选时落到第一条 |
| 打开详情 | 焦点移到“返回”按钮，读屏和键盘用户不会丢失位置 |
| 归档 | 详情页归档/取消归档即时生效，无二次确认（可逆） |
| 移入回收站 | 两步确认：第一次点击变为“确认移入回收站”，再次点击才执行；任何重新渲染/切换条目都会复位 |
| 历史版本 | 按需读取，读取中按钮禁用并显示“正在读取…”，成功后变为“刷新历史版本”，失败显示可重试提示 |
| 列表加载 | 切换筛选时显示“正在读取…”，列表带 `aria-busy`，读屏可感知 |
| 空状态 | 已归档为空显示“暂无已归档条目”，搜索无结果显示“没有匹配的条目” |

### 页面内面板与保存提示

| 交互 | 行为 |
| --- | --- |
| 内联菜单/验证码/粘贴/二维码面板 | `↑`/`↓` 在操作间循环，`Home`/`End` 跳首尾，`Esc` 关闭并把焦点还给输入框或锚点 |
| 聚焦打开 | 显式命令打开菜单时聚焦首个操作；聚焦触发的菜单保持输入焦点 |
| 保存横幅 | 打开时聚焦标题输入框；`Esc` 等于“暂不保存”（不会误保存）；`Enter` 执行主操作（更新或保存），忽略输入法组合态 |
| 保存结果 | 成功后面板关闭并提示；失败保留横幅与可重试状态 |
| 二维码/验证码 | 保存需要显式点击，`Esc` 只关闭不保存 |

### 选项页与系统设置

| 交互 | 行为 |
| --- | --- |
| 空闲锁定 | 下拉选择 0/1/5/15/30/60 分钟；默认关闭；说明与权限理由同步在发布文档 |
| 通知 | 默认关闭；只对保存成功和空闲锁定发通知 |
| 诊断 | 一键导出 JSON，状态行用 `role="status"` 播报成功/失败 |
| 动画 | 选项页与弹窗都尊重 `prefers-reduced-motion` |

## 视觉与结构验证

用仓库内的 Chromium for Testing（Playwright 缓存 1248）加载真实构建的 `popup.html`，配合一个只用于截图的 `chrome` API 桩，渲染了四个状态：金库、已归档、详情、历史版本。截图保存在 `.tmp/ui-shot/`（不提交）。这一轮通过截图发现并修正了两处真实问题：

1. 收藏星标原先直接 `prepend` 到网格行，挤占标题列，导致标题错位；现改为与图标一起放进标题。
2. 已归档筛选在等待新搜索结果时会短暂显示上一条目的条目；现在先按 `state === "archived"` 本地过滤。

截图不是端到端验收：没有真实原生宿主、真实 1Password 界面或 Playwright 完整脚本，不能据此宣称“与 1Password 完全一致”。

## 仍未覆盖的交互

- 真实 1Password 扩展的逐项并排对比（键盘、读屏、动画时序）；本机没有安装参考扩展。
- 真实原生会话下的保存、更新、Passkey、银行卡、OTP、历史恢复的完整旅程；现有证据仍是 Node DOM + Go 单测。
- 触摸/移动端、Safari 容器 App 的交互；这些走各自的原生界面，不在扩展弹窗范围内。
- 通知在真实桌面上的展示时机与图标（数据 URL 图标未在真实通知中心验证）。
- 空闲锁定的真实浏览器触发阈值（`idle` 权限的事件时序未在真实浏览器测量）。
